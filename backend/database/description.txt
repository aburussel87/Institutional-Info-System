
University Institutional Information System - Full Project Report


2. Abstract
-----------
This project presents the design and development of a full-stack University Institutional Information System that automates and integrates various academic and administrative functionalities of a university. The system is capable of handling student registration, exam scheduling, fee tracking, role-based user interaction, and dynamic data reporting. The backend is built using Node.js and Express.js, the frontend is developed using React.js, and data is managed with a robust PostgreSQL database enhanced by PL/pgSQL functions and triggers. The system improves operational efficiency, minimizes paperwork, and enhances real-time decision-making in an academic institution.

3. Introduction
---------------
Universities manage vast amounts of data related to students, teachers, courses, exams, halls, and administrative tasks. Traditionally, these processes are handled manually or through fragmented tools. This project addresses the need for a centralized, web-based system that simplifies and unifies these operations. It empowers students, teachers, advisors, heads of departments (HODs), provosts, and administrators with tailored dashboards and workflows based on their roles.

4. Objectives
-------------
- Provide a centralized platform for managing academic and administrative data.
- Implement secure, role-based access for students, teachers, and admins.
- Automate course registration, exam scheduling, and grade management.
- Enable real-time data visualization for departments, halls, and advisors.
- Streamline hall and advisor allocation using automated triggers.

5. System Overview
------------------
The system consists of three major components:
- Frontend: A responsive and interactive UI built with React.js and Bootstrap.
- Backend: RESTful API using Node.js and Express.js, handling business logic and authentication.
- Database: A normalized PostgreSQL schema supported by stored procedures and triggers for data consistency and automation.

Users log in using JWT-based authentication. Depending on their role, they are redirected to their respective dashboards (Admin, Student, Teacher, Advisor, HOD, Provost) with access to relevant features and data visualizations.

6. System Architecture
----------------------
React Frontend → Express Backend → PostgreSQL Database
(JSON API)      (Business Logic)   (SQL Functions, Triggers)

7. Key Features
---------------
- Authentication and Role Management:
  - Secure login with JWT
  - Role-based dashboards for Admin, Teacher, Student, Advisor, Provost, and HOD

- Teacher Dashboard & Multi-Role Context:
  - Teachers dynamically see context-based data based on their designation:
    - As a Provost – Can view all students residing in their hall
    - As an Advisor – Can view and advise their assigned students
    - As a HOD – Can view all teachers and students of their department
  - All role-specific data is fetched from the backend via functions like get_teacher_context() and get_teacher_info()

- Contextual Notification System:
  - Teachers can send notifications based on their authority:
    - To specific students
    - To a course section they teach
    - To their department (if they are HOD)
    - To their hall students (if they are Provost)
  - The database handles this logic via the get_notifications() and get_user_notifications() functions, which intelligently filter and deliver notifications based on user role and scope.

- Course & Exam Management:
  - Teachers can view course assignments
  - Add exams and course materials 
  - View enrolled students for each course

- Fee Management:
  - Students can track individual fees (exam, dining, hall, registration, etc.)
  - Payment status is categorized as Paid, Unpaid, or Partial
  - Admins and students can view chronological payment histories

- Course Registration & Results:
  - Students can register for available courses based on their department and semester
  - Pre-requisite checks and failure recovery handled via PL/pgSQL logic
  - Triggers automatically update grade sheets and missed courses

- Admin & Dashboard Analytics:
  - Department-wise, Hall-wise, and Advisor-wise student summary
  - Real-time visualization using Chart.js for quick insights
- Deployment:
  - Deployed on cloud platform (e.g., Render/Vercel)
  - Mobile-friendly version (React Native / PWA)

8. Database Schema Overview
---------------------------
- Over 25 tables and ENUM types including: User, Student, Teacher, Course, Enrollment, Exam, ExamResult, StudentFee, Hall, EmergencyContact, etc.
- Core ENUMs: userrole, examtype, feestatus, roomtype, gender, semester
- 70+ SQL functions and triggers: get_teacher_info, get_student_full_info, assign_random_provosts_to_halls, get_student_grades, update_gradesheet, etc.
- Triggers: Auto-population of missed courses, automated exam result generation, cascade updates to hall assignments

9. Technologies Used

10. Implementation Details
---------------------------
- Backend uses modular routing (e.g., dashboardRoutes.js, authRoutes.js)
- Frontend has dedicated role-based pages and reusable components
- API communication uses Axios for secure data fetching and updates
- Example: Student course registration triggers grade sheet updates
